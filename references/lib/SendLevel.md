# SendLevel

Controls which artificial keyboard and mouse events are ignored by hotkeys and hotstrings.

```ahk
PrevLevel := SendLevel(Level)
```

<a id="Parameters"></a>
## Parameters

**Level**

Type: [Integer](../Concepts.md#numbers)

An integer between 0 and 100.

<a id="Return_Value"></a>
## Return Value

Type: [Integer](../Concepts.md#numbers)

This function returns the previous setting.

<a id="General_Remarks"></a>
## General Remarks

The default send level is 0, meaning [hook](_UseHook.md) [hotkeys](../Hotkeys.md) and [hotstrings](../Hotstrings.md) ignore keyboard and mouse events generated by any AutoHotkey script. In some cases it can be useful to override this behavior; for instance, to allow a remapped key to be used to trigger other hotkeys. SendLevel and [#InputLevel](_InputLevel.md) provide the means to achieve this.

SendLevel sets the level for events generated by the current [script thread](../misc/Threads.md), while #InputLevel sets the level for any hotkeys or hotstrings beneath it. For any event generated by a script to trigger a hook hotkey or hotstring, the send level of the event must be higher than the input level of the hotkey or hotstring.

Compatibility:

- [SendPlay](SendMode.md#Play) is not affected by SendLevel.
- [SendInput](SendMode.md#Input) is affected by SendLevel, but the script's own hook hotkeys cannot be activated while a SendInput is in progress, since it temporarily deactivates the hook. However, when Send or SendInput [reverts to SendEvent](SendMode.md#SendInputUnavail), it is able to activate the script's own hotkeys.
- [Hotkeys](../Hotkeys.md) using the ["reg"](ListHotkeys.md) method are incapable of distinguishing physical and artificial input, so are not affected by SendLevel. However, hotkeys above level 0 always use the keyboard or mouse hook.
- [Hotstrings](../Hotstrings.md) use #InputLevel only to determine whether the last typed character should trigger a hotstring. For instance, the hotstring `::btw::` can be triggered regardless of #InputLevel by sending `btw` at level 1 or higher and physically typing an [ending character](../Hotstrings.md#EndChars). This is because hotstring recognition works by collecting input from all levels except level 0 into a single global buffer.
- Auto-replace [hotstrings](../Hotstrings.md) always generate keystrokes at level 0, since it is usually undesirable for the replacement text to trigger another hotstring or hotkey. To work around this, use a non-auto-replace hotstring and the SendEvent function.
- Characters sent by the [ASC (Alt+nnnnn)](Send.md#asc) method cannot trigger a hotstring, even if SendLevel is used.
- Characters sent by SendEvent with the [{Text}](Send.md#SendText) mode, [{U+nnnn}](Send.md#Unicode) or [Unicode fallback method](Send.md#characters) can trigger hotstrings.

The built-in variable [A_SendLevel](../Variables.md#SendLevel) contains the current setting and can also be assigned a new value instead of calling SendLevel.

Every newly launched hotkey or hotstring [thread](../misc/Threads.md) starts off with a send level equal to the [input level](_InputLevel.md) of the hotkey or hotstring. Every other newly launched thread (such as a [custom menu item](Menu.md) or [timed](SetTimer.md) subroutine) starts off fresh with the default setting, which is typically 0 but may be changed by using this function during [script startup](../Scripts.md#auto).

If SendLevel is used during [script startup](../Scripts.md#auto), it also affects [keyboard and mouse remapping](../misc/Remap.md).

AutoHotkey versions older than v1.1.06 behave as though `#InputLevel 0` and `SendLevel 0` are in effect.

<a id="Examples"></a>
## Examples

<a id="ExBasic"></a>

**Example:** SendLevel allows to trigger hotkeys and hotstrings of another script, which normally would not be the case.

```ahk
SendLevel 1
SendEvent "btw{Space}" ; Produces "by the way ".

; This may be defined in a separate script:
::btw::by the way
```
